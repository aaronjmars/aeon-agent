show-hn-draft prompt refresh
The Show HN launch-post template that fires automatically when aeon hits 500 stars just got its first context refresh since early May. Until today the template was framed for a 250-star project 12 days from a 300-star milestone with 90+ skills — none of which describes aeon anymore. With the auto-dispatch wired yesterday and 500 stars projected for Jun 11, the post sitting in articles/ when the trigger fires would have described a different product to thousands of HN readers.

Why this matters:
This is the launch-post-as-content side of the auto-dispatch loop wired by yesterday's PR #358 (star-milestone auto-dispatch). At 500⭐, star-milestone is going to call gh workflow run on show-hn-draft with no human in the middle — and whatever this skill produces is the first impression for HN's front page. The early-May framing pre-dated three install paths, the onchain security layer, the external skill-packs ecosystem, and the move from 5 to 8 skill categories. A prompt-only refresh closes that gap before the launch fires.

What was built:
- skills/show-hn-draft/SKILL.md launch-trigger framing: "~12 days from the 300-star milestone at ~4/day momentum" → "the 500-star milestone is the auto-dispatch trigger wired by star-milestone — this skill must have a fresh draft sitting in articles/ when that fires"
- skills/show-hn-draft/SKILL.md project-scale shorthand: "~250 stars, growing autonomous-agent narrative" → "~500 stars, ~165 forks, ~195 skills across 8 categories, an external skill-packs ecosystem, and an onchain security layer"
- skills/show-hn-draft/SKILL.md title example: "90+ skills" → "195 skills"
- skills/show-hn-draft/SKILL.md body §2 hint: explicit pointer at three non-obvious capabilities the LLM should consider for the senior-engineer surprise — onchain security (vigil + wallet-risk-weekly + vigil-revoke), three install paths, external skill-pack inflow from Nurstar/vigilcodes/HoundFlow/signa/Careful Finance/Mneme. Hard cap: pick ONE
- skills/show-hn-draft/SKILL.md launch checklist + edge case: 300-threshold language → next-round-number language (500, 750, 1000) so the skill stays correct past 500⭐; edge case explicitly names star-milestone as the auto-dispatcher

How it works:
This is a prompt refresh, not a code change — show-hn-draft writes the launch post by reading README/skills.json/aeon.yml/articles/memory at runtime, so every live number is pulled dynamically. What changed is the framing prose around those inputs: the LLM now knows what scale the project is at, what star-milestone is going to do at 500⭐, and which three non-obvious capabilities are worth surfacing as the hook. Hard rules (no marketing, no emoji, no invented numbers, ≤350 words, single link in paragraph 4) and the variant trio (Show HN + r/MachineLearning + r/selfhosted) are unchanged.

What's next:
First test fires when aeon hits 500⭐ — projected Jun 11 at v7 ≈3.6/day momentum. star-milestone's auto-dispatch then triggers show-hn-draft with var="" so the full variant trio writes to articles/, then the operator's launch checklist gates the actual posting decision.
