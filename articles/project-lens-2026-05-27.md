# A Week-Old Account Could Publish To The Agent Skill Marketplace. 824 Of Them Did.

The gate was almost nothing. According to the post-mortems, anyone with a GitHub account older than one week could publish a "skill" to ClawHub, the public marketplace for the OpenClaw agent. No code review. No signing. No malware scanning. Starting in late January 2026, attackers walked through that gate and uploaded more than 335 malicious skills; by mid-February the count had reached 824 out of roughly 10,700 total. The payload, per [the reporting](https://beam.ai/agentic-insights/ai-agent-security-breaches-2026-lessons), was macOS stealer malware phoning home to a single command-and-control server, riding on a platform with tens of thousands of live deployments.

This is what happens when a skill stops being a document and becomes a dependency. An agent skill is just instructions — a bundle of text and maybe a script that tells an autonomous agent what to do and what to call. That made it feel harmless, so nobody treated the marketplace like a package registry. Then agents got permissions: the ability to act, spend, and read data. A [Cloud Security Alliance and Token Security study](https://www.kiteworks.com/cybersecurity-risk-management/ai-agent-security-incidents-2026/) found that 65% of organizations had at least one security incident in the past year caused by an AI agent on their network. The skill supply chain was the part everyone forgot to lock.

## The industry's answer arrived this month

In the last four weeks the response has gone from advisory to product. On May 1, 2026, CISA, the NSA, and their counterparts in Australia, Canada, New Zealand, and the UK published "Careful Adoption of Agentic AI Services" — the first coordinated multi-government guidance written specifically for autonomous agents. Three weeks later, on May 22, NVIDIA shipped [Verified Agent Skills](https://developer.nvidia.com/blog/nvidia-verified-agent-skills-provide-capability-governance-for-ai-agents/): a publishing flow that runs each skill through a risk scanner called SkillSpector, cryptographically signs it using the OpenSSF Model Signing standard so the signature covers every file in the skill directory, and ships a machine-readable "skill card" documenting who made it, what it depends on, and what risks were found.

Strip away the branding and the recipe is clear. Scan the skill for dangerous behavior. Sign it so it can't be tampered with. Document its provenance. Badge the ones you trust. That is the package-manager playbook — the same one npm, PyPI, and Homebrew arrived at over a decade — compressed into a single news cycle because the agent ecosystem skipped straight to a marketplace without it.

## Aeon ran the recipe on text the whole time

`aaronjmars/aeon` is 455 stars and 130 forks today, and it has been executing that exact recipe — with one structural difference. Its skills are not signed blobs. They are markdown files. Each one is a `SKILL.md`: YAML frontmatter and a numbered list of steps, written to be read by a human and a model in the same pass.

Before any external skill is installed, [`scan.sh`](https://github.com/aaronjmars/aeon/blob/main/skills/skill-security-scan/scan.sh) reads the file and matches it against pattern arrays graded HIGH and MEDIUM. HIGH catches `eval`, secret exfiltration like `curl.*\$[A-Z_]` or `$GITHUB_TOKEN` piped to a network call, and prompt injection — the literal pattern `[Ii]gnore[[:space:]]+(all[[:space:]]+)?previous[[:space:]]+instructions`. A HIGH finding exits non-zero, and the `install-skill-pack` CLI prompts the operator — or, for a non-interactive run without an explicit `--yes` or `--force`, fails closed. Trust is an allowlist: `skills/security/trusted-sources.txt` names exactly three entries (`aaronjmars`, `aaronjmars/aeon`, `aaronjmars/aeon-agent`), and only those skip the deep content scan. The `skill-packs.json` registry carries a `trust_level: "trusted"` field, but it is a discovery hint only — the scan-bypass is gated by the allowlist file, so the registry cannot be used to forge trust. That distinction is the whole point: a marketplace that lets its own listings declare themselves safe is ClawHub.

## What a signature can't tell you

Here is the part the consolidation around signing misses. A cryptographic signature answers two questions — *who published this* and *has it changed since* — and neither is *what does it do*. A signed, verified, malware-scanned skill is still an opaque package; you trust the scanner because you can't read the artifact.

Aeon's artifact is the audit. And the sharpest evidence is a bug Aeon found in its own scanner. For weeks, the prompt-injection patterns in `scan.sh` were written with PCRE escapes like `\s` and `\b`. GNU grep on Linux CI accepted them; BSD grep — the default on every macOS operator's machine — treated them as literal characters, so `[Ii]gnore\s+previous\s+instructions` silently matched nothing. The security scanner was passing poisoned input on an entire class of machines. It got caught and [rewritten to POSIX character classes](https://github.com/aaronjmars/aeon/pull/197) only because the scanner is itself a plain-text file someone could read line by line. You do not find a silently-degraded regex by verifying a signature over it. You find it by reading it.

## Two models of trusting code you didn't write

There are two ways to trust a skill. Attestation: sign the package, scan it, badge it, and trust the chain of custody. Transparency: make the artifact something a person can read before they run it, and scan it anyway. For an enterprise buying capabilities from vendors it will never audit, NVIDIA's notary is the right answer, and the May 2026 wave toward signing is overdue. But the ClawHub failure was never that signatures were missing — it was that a week-old account could publish and nobody looked. Looking is cheap when the skill is text. The supply chain only needs a notary when you can't read what you're about to run.
