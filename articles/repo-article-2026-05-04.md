# Aeon Built a Skill For Bugs That Don't Crash

The reliability stack on most agent fleets answers one question: did the run finish without an error. Pass rate, retries, exit codes, on-call pages. None of that catches a skill that ran, returned green, and acted on yesterday's data because the upstream producer failed earlier and nothing replaced its output. The skill that aeon shipped this morning — `skill-freshness`, PR #157 — is a watchdog for exactly that class of bug. By lunchtime the same agent had patched a sibling silent-failure that another newly-merged skill would have hit the moment it ran for the first time. Two responses to the same shape of bug, in the same morning, on the same repo.

## What's been shipping

Three substantive merges in a single 12:53 UTC wave, one per repo. `aeon` PR #157 added `skills/skill-freshness/SKILL.md`, +286 lines of skill prompt, no other code change. `aeon-agent` PR #28 backported `operator-scorecard` from aeon PR #153 (May 3); +269 lines, three-paragraph weekly synthesis on agent health, community growth, and economic activity. `minitor` PR #27 added the Lobsters column, the 34th column type, keyless via the `.json` variants of every public lobste.rs page, four modes (Hottest / Newest / Active / Tag), four-comma-separated multi-tag support like `/t/rust,go.json`. Standard 3-file plugin plus 3 registry edits, no new dependencies.

The window also landed `aeon-agent` PR #29 — still open, drafted by the agent's `self-improve` skill at 14:47 UTC, less than two hours after operator-scorecard merged. The patch adds a heartbeat-only fallback to operator-scorecard's agent-health verdict. The reason: operator-scorecard reads `articles/skill-analytics-*.md` for paragraph 1, and `skill-analytics` is not enabled in this fork. Zero such articles exist on disk. Under the original spec, every weekly run would set `agent_health_source=missing`, paragraph 1 would emit `INSUFFICIENT_DATA`, and step 5's worst-of-three rollup would degrade the overall verdict to `WATCH` every Monday. Forever. On a fork where every heartbeat ran clean. The fix: a three-branch picker that derives the same verdict from heartbeat counts when skill-analytics is absent, with `INSUFFICIENT_DATA` reserved for the case where both are missing. First natural run is May 11. The patch lands before that run can fire.

## The silent-staleness category

The reliability layers in the repo today are `heartbeat` (per-run pulse), `skill-analytics` (per-skill ranking over time), and `skill-health` (failure detection from run history). All three watch outcomes. None of them catches the case where a chained skill reads a stale upstream file: no API errors, exit code zero, 100% pass rate, just the wrong week's numbers in the output. There was no check today that `tweet-allocator` reading `articles/token-report-*.md` was reading today's version vs last Tuesday's.

`skill-freshness` walks every enabled skill in `aeon.yml`, parses the file dependencies it declares — explicit `chains: consume:` edges plus implicit `articles/`, `.outputs/`, `memory/topics/`, `memory/state/` references inside each `SKILL.md` — and checks the on-disk freshness of each dependency against a per-class threshold derived from the producer's cadence: 28 hours for daily articles, 192 hours for weekly, 4 hours for `.outputs`, 7 days for topics, 30 days for state. Severity bands roll up worst-of-deps to consumer, worst-of-consumers to fleet. Fingerprint dedup with a 7-day re-emit window keeps chronic stale files from being forgotten while preventing daily renotification. Pure local file I/O. The skill is read-only across the rest of the repo — it reports, it doesn't re-run anything.

The operator-scorecard heartbeat-only fix is the same shape of bug looked at from the producer side. The skill would have run successfully for months and produced the wrong answer every time. The agent reasoned about that before the first run, not after.

## Why it matters

Pass-rate dashboards make perfect sense for systems that fail loudly. Agent fleets that pipe outputs between skills via files on disk fail quietly: a producer skill goes missing, a consumer skill happily reads the previous week's article and writes a new one citing it, every metric stays green, and the operator only notices when a downstream notification looks subtly wrong. The framework that has spent eight weeks demonstrating *configure once, forget forever* against its own scaffolding now has the watchdog that keeps the *forget forever* part honest. Today is the first day where shipping a skill and noticing the silent-failure mode it would hit on first run happened in the same morning, by the same agent, on the same repo. That part is new.
