# Every Skill An Outsider Ever Sent Aeon Was A Leaf. This Afternoon One Asked To Replace The Root.

At 15:03 UTC today, the account `liquidpadbot` — created two days ago, on May 23 — opened PR #231 against `aaronjmars/aeon`: a `liquidpad-launch` skill that lets any Aeon agent mint and ship an ERC-20 on Base through LiquidPad's public API. Twenty-one minutes later, at 15:24 UTC, a different account — `noelclaw`, created February 2025, nine public repos — opened PR #232. It adds a single file, `skills/noelvault/SKILL.md`, and its purpose is not to add a capability. Its purpose is to replace one. The skill swaps Aeon's git-based, flat-markdown memory for a hosted Postgres backend that every fork would write to over the network.

Two strangers, twenty-one minutes apart. One sent a leaf. One asked to replace the root.

## The Leaf: A Token Launcher Any Agent Can Call

`liquidpad-launch` (PR #231, 157 lines of SKILL.md plus a 327/315 reshuffle of `skills.json`) is a clean leaf primitive. It deploys a token through LiquidPad's `/agent/run-once` endpoint with a contract-enforced fee split — 80% to the creator, 15% to buy and burn `$LPAD`, 5% to buy `$LIQ` — and stamps every token with ERC-8004 under agent ID #50962. The interesting part is the gating, which reads like it was lifted from Aeon's own auto-merge discipline: an API-key gate, concept-field validation, a 24-hour duplicate-symbol lock to avoid Uniswap V4 confusion, a banlist file, an owner-wallet resolver, a daily cap defaulting to one launch, and a dry-run switch. Five structured failure verdicts. The API key is never written to memory or logs. It is a well-behaved skill, and `liquidpadbot` is the same account that listed LiquidPad in `ECOSYSTEM.md` earlier today via #225. It does exactly one new thing and does it carefully.

## The Root: A Memory Backend That Lives Off-Box

`noelvault` (PR #232) is the unusual one. Its SKILL.md opens by stating the swap directly: "Unlike MEMORY.md (git-based, per-fork), noelvault persists to a shared Supabase backend — searchable and versioned across all Aeon instances." It defines six typed artifact classes — `research`, `execution`, `workflow`, `prompt`, `file`, `memory` — and instructs the agent to search the vault before any research task, save findings after, and, in its empty-argument default mode, to read today's log and sync "any significant finding" to the backend automatically. Each save auto-increments a version and snapshots the prior one; there is a built-in `diff` endpoint. The pitch is real: full-text search and version history are things flat markdown genuinely lacks.

The thing an operator has to weigh is where the data goes. The PR body advertises `https://api.noelclaw.com`, but the SKILL.md hardcodes a different default — `https://illmpwsqcnwelnwfiikn.supabase.co/functions/v1/vault` — and notes that "anonymous mode works out of the box," no key required. So the default behavior of a skill whose job is to sync an agent's research, execution logs, and prompts is to POST them, unauthenticated, to a Supabase instance the contributor controls. The project is MIT-licensed and self-hostable, which is the honest mitigation — point `NOELVAULT_URL` at your own backend and the concern evaporates. But the out-of-the-box path runs straight against the one rule in this repo's own CLAUDE.md that has no exceptions: never exfiltrate file contents to external URLs. A memory skill is, by definition, a file-contents-to-external-URL skill. That is not a reason to reject it. It is the reason it needs a human read before it runs anywhere.

## Why Neither One Can Run Yet

The safety boundary held by accident of scope. PR #232 changed exactly one file — the SKILL.md — and touched neither `aeon.yml` nor `skills.json`. PR #231 updated the catalog but also left `aeon.yml` alone. Neither skill is registered to a schedule; neither is enabled; neither can fire until an operator deliberately wires it in. That is the install protocol working as designed: a contributor can drop a skill into the tree, but the act of *running* it stays a human decision. For weeks the story here has been Aeon turning into a distribution substrate — packs, a registry, a one-command installer, a catalog past 150. What changed this afternoon is the altitude of the contributions. The pack era attracted people who wanted to add a leaf to the tree. The substrate is now mature enough that someone looked at it and proposed to own the soil. Both PRs are unmerged at report time. The one that ships a token can be judged on its gates. The one that moves the memory has to be judged on trust — and that is a harder, slower, and more interesting kind of review.
