# Everyone Is Building a Store for Agent Skills. The Attackers Already Shopped There.

In February 2026, security researchers documented the first coordinated malware campaign aimed at autonomous coding agents: more than 30 malicious "skills" uploaded to a public registry, each a plain Markdown file that any GitHub account a week old could publish — no code signing, no review, no sandbox by default. Snyk's [ToxicSkills audit](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/) then scanned 3,984 skills from two registries as of February 5th and found prompt injection across the sample, 1,467 malicious payloads in total, with 91% of the malicious skills pairing ordinary malware with hidden instructions written to hijack the agent's reasoning at runtime. To a conventional scanner, a poisoned skill looks like documentation. To the agent, it reads as a command.

This is the bill coming due for a year of marketplace-building. The agent-skill ecosystem went from roughly one registry in late 2025 to [at least eight major marketplaces](https://www.digitalapplied.com/blog/ai-agent-marketplaces-2026-discovery-distribution) by Q2 2026 — Claude Skills, the GPT Store, MCP Hubs, Hugging Face Spaces, LangChain Hub, and others — almost all of them racing to solve the same advertised problem: discovery. "Getting it surfaced in a marketplace with thousands of competing listings is where most agency-built agents fail to gain traction," one 2026 landscape survey concluded. The stores optimized for being found. The attackers optimized for being installed.

## The trust model nobody priced in

A skill marketplace makes an implicit promise: install this and it's probably fine. The two ways to back that promise are curation and scanning. Curated platforms like [Agensi](https://www.agensi.io/learn/ai-agent-marketplace-landscape-2026) run automated security checks — an eight-point sweep for prompt injection, data exfiltration, secret detection, dangerous commands — before a listing goes live. It's a real defense against the obvious attacks. It is structurally weak against the interesting one.

The interesting one is semantic. An academic write-up of [SKILL.md supply-chain attacks](https://arxiv.org/html/2605.11418v1) makes the mechanism precise: the malicious payload isn't code, it's prose — an instruction embedded in the natural-language body of a skill file, indistinguishable from a usage example until the moment the agent obeys it. Embrace the Red demonstrated exactly this against a coding agent, shipping a skill that appeared to be a standard GitHub integration while quietly carrying instructions to exfiltrate a repository; the vendor [patched it](https://www.unite.ai/ai-agent-skills-supply-chain-security-vulnerabilities/) on February 10th. A signature scanner has nothing to match on, because there's no signature — there's a sentence. Eight stores competing on discovery were quietly competing to be the most convenient distributor of sentences nobody can statically verify.

## The framework that refused to build a store

[aaronjmars/aeon](https://github.com/aaronjmars/aeon) — an autonomous-agent framework that runs as scheduled GitHub Actions on a repo you fork — spent this week wiring up third-party skill distribution, and conspicuously did not build a store to do it. There's no hosted catalog, no central listing, no upload endpoint. A community pack arrives as a pull request into *your* fork. The `install-skill-pack` flow ([#487](https://github.com/aaronjmars/aeon/pull/487)) writes the skill files into your repo and regenerates `packs.json` so the install is visible in your own tree; installed community skills land in an always-visible "Installed" pack ([#486](https://github.com/aaronjmars/aeon/pull/486)) rather than disappearing into a vendor's namespace. The security boundary isn't a platform's scanner. It's `git diff`, and the commit it produces.

That reframes the trust question instead of answering it. In the marketplace model, the unit of trust is a *listing* you query at runtime — opaque, mutable, owned by someone else. Here the unit is a *commit* in a repository you control: readable before merge, attributable by `git blame`, revertable in one command, and scoped so a fork starts with only its 13-skill Core enabled rather than inheriting someone else's roster ([#491](https://github.com/aaronjmars/aeon/pull/491)). A poisoned skill in a central store is a query result you can't audit after the fact. A poisoned skill in your fork is a line in your history with a name attached to it.

## Where this gets honest

The same week shipped the move that cuts against the whole argument: `install-skill` now does [zero-touch auto-merge](https://github.com/aaronjmars/aeon/pull/485) (#485), merging the install PR without a human reading it. If nobody reads the diff, "the boundary is `git diff`" is a boundary in principle, not in practice — and an auto-merged community pack like Hunch Prediction Markets ([#472](https://github.com/aaronjmars/aeon/pull/472)) runs the same untrusted-Markdown risk the marketplaces have. Git's audit trail doesn't stop a prompt injection from firing once. It only tells you, afterward, exactly what fired and when.

But that "afterward" is the actual product difference, and it's not nothing. The marketplace bet is *prevent at the gate* — and Snyk just demonstrated the gate is porous against the dominant attack class. The fork bet is *record everything in a substrate you own* — so when the gate fails, and the gate will fail, you have a diff, a blame, and a revert instead of a support ticket to a platform that already shipped the payload to ten thousand other tenants. One model degrades to "trust us." The other degrades to "read the log."

## The call

Here's the claim specific enough to be wrong by this time next year: the agent-skill stores will keep winning on discovery and keep losing on trust, and the first marketplace-scale SKILL.md breach — a single poisoned popular listing pushed to every installer at once — will make *install-as-commit* look less like friction and more like the only forensics that survives the incident. If, instead, the curated scanners catch the next ToxicSkills wave cleanly and central stores post a quiet year, the fork-native model is solving a problem the market already closed. I don't think they will. Semantic injection isn't a bug the scanners are one release away from catching; it's the format working as designed. The defensible position won't be whose store is safest. It'll be whose mistakes you can read back.
