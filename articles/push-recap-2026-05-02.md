### External security fix from tomscaria
**Summary:** Sole external commit in the window: a tight 6-line shell-injection fix on the dashboard's secrets API. The `POST /api/secrets` and `DELETE /api/secrets` handlers each interpolated user-controlled fields into a shell string passed to `execSync('gh secret set ...')` / `execSync('gh secret delete ...')`. The POST handler's only escape was `value.replace(/"/g, '\\"')` — payloads containing `$(...)`, backticks, `;`, `&&`, `|`, or backslash still injected. The DELETE handler had no escape on `name` at all (the `VALID_SECRET_NAME` regex was defense in depth, not the shell barrier).

**Commits:**
- `342c7a3` — fix(dashboard/secrets): use execFileSync to close shell-injection on secret set/delete [PR #150, open, by tomscaria, 2026-05-01T17:19:08Z]
  - Modified `dashboard/app/api/secrets/route.ts` (+3, -3) — both call sites switched from `execSync` (shell-invoking template-string) to `execFileSync('gh', [...args], opts)` (spawns gh directly, no shell, argv-passed). `name` and `value` cannot inject regardless of contents. The now-unnecessary quote-escape on `value` is dropped. The `VALID_SECRET_NAME` regex check on `name` is kept as a second line of defense. The two read-only call sites (`gh auth status`, `gh secret list`) take no user input and are left as-is.

**Impact:** Direct security fix on the only dashboard endpoint that accepts user-controlled values and executes a shell command. Three lines added, three lines removed; no API or schema change. Tomscaria — the operator behind the most-active fork (94 skills per Apr-26 leaderboard) — is also the second external contributor to ship a security-class fix here in two weeks. PR is open and unlabeled at recap time; `pr-triage` is shipped but still `enabled: false`, so the first-touch label/comment hasn't fired.
