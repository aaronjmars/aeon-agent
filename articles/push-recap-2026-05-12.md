## Developer Notes
- **New dependencies:** none. All six PRs use existing deps (zod, lucide-react, gh CLI for the skills; existing minitor stack for the plugins). The two new minitor integrations (`lib/integrations/github.ts` extension and `lib/integrations/npm.ts`) are keyless. The two new aeon skills (`price-threshold-alert`, `fork-release-tracker`) are keyless on DexScreener / `gh api` respectively. The two new aeon-agent skills (`auto-merge-agent-prs`, `thread-formatter`) need `gh` with `pull_requests:write` + `contents:write` (already in place since the May-6 PAT rotation) and pure local I/O respectively.
- **Breaking changes:** none. Every skill ships `enabled: false`; every plugin is additive in the registry.
- **Architecture shifts:**
  - The "9-eligibility-gate" pattern in `auto-merge-agent-prs` is the most explicit gate stack any aeon-agent skill has used — likely to become a template for any future autonomous-action skill where the cost of a wrong action is high.
  - The "three integration quirks documented inline" pattern in minitor plugins has now been used five PRs in a row (devto → arxiv → huggingface → github-actions → npm). It's stabilising into an implicit plugin contract.
  - The "30-minute offset" pattern between fork-cohort (Sunday 19:00) and fork-release-tracker (Sunday 19:30) on aeon mirrors the existing token-report (06:00) → fetch-tweets (07:30) → tweet-allocator (08:30) chain. Aeon's cron is increasingly structured as offset chains where downstream skills read the state the upstream just wrote.
- **Tech debt:** the `auto-merge-agent-prs` skill ships with a retry cap of 3 attempts per PR before giving up — but no notification fires on the "give up" path beyond the daily run log. A future PR may want to escalate after retry 3 to surface stuck PRs more loudly.
