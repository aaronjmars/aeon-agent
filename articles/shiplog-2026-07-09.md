## the secretcurl overhaul

this was the biggest structural fix of the window, and it compounds across every fork.

the original sandbox limitation: env vars can't expand in curl headers during a GitHub Actions run. the workaround was a whole prefetch/postprocess dance — `scripts/prefetch-*.sh` ran before Claude, cached data to disk, skills read from cache. it worked. it was also a footgun. every new auth'd API connection required a new prefetch script, a new cache path, docs to explain it.

PRs #684–#696 killed it. `./secretcurl` now handles authenticated API calls directly in-run — skills pass the endpoint and the framework injects credentials. XAI skills (#687), CoinGecko/Alchemy/Etherscan (#689), GitHub reads (#691), irreversible sends (#695) — all ported. prefetch-xai.sh is gone (#685, #690). the dead postprocess scripts are gone (#695).

the skill instruction changed from "sandbox blocks network, use prefetch cache" to "use secretcurl." one step instead of three. every fork that ships from now on gets this by default.

PR #692 updated the skill docs to match: "sandbox blocks the network" was a myth from the start — the real constraint was env-var injection. myth killed, docs updated.

## skill-execution attestation

PR #650 wired Sigstore provenance into every skill execution. #651 documented it. #652–#653 signed an immutable run-scoped snapshot alongside the output.

aeon's pitch has always been "public traces or it's useless." GitHub Actions logs are public, but they're trust-me-bro: you see what ran, not a proof. Sigstore adds the cryptographic layer — each run signs a manifest, checksum verifiable against the public Rekor log.

forkers get this for free. not "your agent ran this." "your agent ran this, signed, verifiable."
