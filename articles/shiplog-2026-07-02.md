# aeon Spent Six Months Adding 187 Skills. This Week It Deleted 85 of Them.

*shiplog · June 25 → July 2, 2026*

---

The dominant instinct in autonomous agent frameworks is to add. More skills, more coverage, more surface area. aeon followed that instinct all the way to 187 skills. Then stopped. Then cut 85 of them.

This week's shiplog is about what happens after the accumulation phase ends.

---

## The Consolidation

The biggest structural move of the window was a two-phase consolidation of the skill catalog: **187 → 102**. Not a prune — a reorganization. 85 overlapping skills were merged into 49 topic hubs (PR #583). 16 dead skills were deleted outright (PR #581). The count dropped almost in half. The catalog is navigable now.

This matters to forks. The first thing a new forker sees is the skill list. At 187, it was a wall. At 102, it's a menu. The audit burden drops proportionally. Every skill you don't install is a skill that can't go rogue.

Catalogs were regenerated (PR #584) and synced to the website (PR #112, aeon-website) — 102 skills reflected everywhere.

## Feature Sprint

While cutting, the framework also shipped:

**Claude Sonnet 5 live on aeon** (PR #572, Jun 30). The latest Anthropic model is available immediately. Model-agnostic harnesses live or die by how fast they pick up new models. Same day.

**Telegram: slash commands, buttons, deep links, force-reply** (PR #578, Jul 1). Until now, Telegram was a notification channel. Now it's an interface. Slash commands, inline buttons, deep-linked flows. Full interactivity in the channel where most operators already live.

**bankrbot one-click skill install**: The @bankrbot terminal now lets you discover and install aeon skills in a single click. Zero fork friction. The install is a commit; the commit is the audit trail. (83 likes, 4,550 views — the signal hit.)

**@AskVenice gateway support**: Venice joins the gateway lineup. The multi-provider fallback now has another route.

**CLAUDE.md architecture overview** (PR #576): The config file builders read first now has an actual architecture overview — what runs where, what's optional. Another fork-onboarding fix.

## Hardening Trilogy (Jun 25–27)

Eleven PRs (#545–#557) that shipped earlier in the window:

- **Read-only skills**: a hijacked skill can't commit, push, or edit files. The attack surface for supply-chain compromise shrinks to read operations only.
- **Health issue filing**: broken skills no longer die silent — they file a 👍/👎 health issue with context.
- **Run-per-issue logging**: every skill run appends to a GitHub issue instead of clobbering one state file. The run ledger is now a thread, not an overwrite.

These are infrastructure, not features. They're what makes the framework trustworthy to fork.
