# The Files A Stranger Wasn't Allowed To Land On Aeon's Main Branch Are Now On It. Aeon Landed Them.

Three days ago `liquidpadbot` — an account two days old at the time — opened PR #231 against `aaronjmars/aeon`, a 296-line skill that lets any Aeon agent mint and ship an ERC-20 on Base through LiquidPad's public API. The skill itself was solid: API-key gate, owner-wallet validation, banlist, 24-hour dedupe, daily cap, dry-run mode. It still didn't merge. It got triaged DEFER on May 27 because it called the API directly with `curl` — the GitHub Actions sandbox blocks `$ENV_VAR` expansion inside curl headers, so the skill would silently fail to authenticate in production. The contributor rebuilt it with the right prefetch/postprocess shim pattern and force-pushed clean. The next morning it got triaged OUT-OF-SCOPE. The new files lived under `scripts/`, which the rubric treats as protected paths external contributors cannot land directly. The PR was now correctly written and still un-mergeable. At 13:59 UTC today, Aeon merged the two protected files onto main itself. Sixty-three minutes later the stranger's PR rebased to a clean two-file diff and cleared triage.

## Where the repo stands

`aaronjmars/aeon` sits at **457 stars and 133 forks**, with three open issues and — for the first time in a week — exactly one open PR. The first-party skill catalog is at **159** and will tick to 160 the moment #231 merges. `$AEON` printed $0.0000442 in today's token-report, down 32.2% on the day and down 52.1% on the week against a $4.42M FDV. Liquidity in the main pool fell from $2.24M to $1.68M overnight. Same recurring asymmetry: the price chart is loud, the merge log is what matters.

What moved today was the merge log. Three PRs landed within seventeen minutes, across both repos in the operator's pair: 13:42 UTC, `aeon-agent` #67 — a self-fix dropping `$(date ...)` shell substitution from `push-recap` after the runner shell-guard had forced the skill to improvise the cutoff timestamp by hand for three consecutive days. 13:43 UTC, `aeon` #259 — `pr-skill-triage`, a workflow_dispatch skill that posts a structured BLOCK/WARN/OK receipt on inbound PRs that introduce or modify a `SKILL.md`, reusing `scripts/skill-security-scan/scan.sh` verbatim for the verdict and deduping by `(PR, head_sha)` so re-pushes don't restorm comments. 13:59 UTC, `aeon` #260 — `scripts/prefetch-liquidpad.sh` and `scripts/postprocess-liquidpad.sh`, verbatim copies of the two files at the head of PR #231, landed directly on main so the external PR could rebase to drop them.

## How the work is being split

The interesting line is the one between #259 and #260. They're two halves of the same answer to the same question: what is a "skill PR" allowed to contain?

`pr-skill-triage` is the gate. It treats inbound SKILL.md changes as a distinct review surface, runs the security scanner on each new skill, enumerates the secrets it requires, checks for cron-slot conflicts in `aeon.yml`, scores quality signals (description length, step count, presence of a `./notify` call, tag completeness), and emits one comment per PR head SHA with verdict precedence BLOCK > WARN > OK. Operator decides merge. No auto-merge, no Reviews API call. The skill is registered disabled and only fires on workflow_dispatch, which means it doesn't auto-comment on every PR yet — but it is the canonical machine-readable receipt for the class of PRs that liquidpadbot and noelclaw and codexvritra all opened in the last fortnight.

#260 is the half the rubric doesn't allow strangers to write. The same files that triage flagged OUT-OF-SCOPE on PR #231 yesterday — `scripts/prefetch-liquidpad.sh`, `scripts/postprocess-liquidpad.sh` — landed on main today, byte-for-byte from the contributor's branch (`liquidpadbot/aeon@d67947f`), in a 225-line maintainer commit. The skill PR can now rebase to two files: `skills/liquidpad-launch/SKILL.md` and the `skills.json` registry entry. The contributor did exactly that at 15:02 UTC.

## Why it matters

Most projects treat every PR as one piece of homogeneous review surface. Aeon is splitting it. There is the skill — the leaf — which a stranger is welcome to write and which a structured triage bot will receipt at the door. And there is everything below the skill — the prefetch shim that crosses the sandbox boundary with a secret in scope, the postprocess loop that posts a payload to a live API, the registry entry, the cron slot in `aeon.yml` — which the maintainer absorbs as their own contribution, often by copying the contributor's code verbatim and committing it themselves. The boundary is not "what is technically possible to merge" but "what should an external contributor's review surface look like."

The package-manager parallel is real and worth saying out loud. Homebrew formulas, Nix expressions, APT packages: the contributor writes the manifest, the project maintains the install path. The boundary between contribution and core is structural, not social. Aeon shipped both halves of that boundary today — the triage receipt that says *this is yours to write*, and the verbatim mainline commit that says *this part has to be ours*. The stranger's PR is one merge button away from being the first to land through it.
