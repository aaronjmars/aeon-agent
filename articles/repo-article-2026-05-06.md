# Aeon Wrote The v4 Migration Guide Two Weeks Before v4 Lands

The framework's biggest redesign in eight months is roughly two weeks out — that much is in the operator's social posts, not yet in the release notes. This morning aeon shipped `v4-readiness`, a workflow_dispatch skill that reads any fork's `aeon.yml`, `skills.json`, and `memory/MEMORY.md` against an embedded v4 change manifest and emits a personalized Safe / Review / Custom / Action breakdown with effort tags. The migration tool exists before the migration. Forty-plus forks running on the current architecture get a structured pre-flight instead of finding out which keys still work after a cron fires on a deprecated config.

## What's been shipping

PR #160 in aeon adds 304 lines across three files, all of them prose: `skills/v4-readiness/SKILL.md`, an entry in `aeon.yml`, and a `skills.json` row bumping the skill total from 110 to 111. The change manifest is seeded with patterns the operator's posts have flagged as in-scope for v4 — the `chains:` runner interface, `reactive:` triggers, schedule syntax, model selector strings, the gateway block, the channels block, MCP server tool naming, the `add-skill` / `add-mcp` / `add-a2a` CLIs, the `skills.json` schema, the dashboard catalog shape — alongside patterns confirmed stable: SKILL.md frontmatter keys, the `./notify` interface, the `memory/` directory layout, the `articles/${skill}-${today}.md` output convention, `watched-repos.md`, `gh api` usage, and the `${today}` template variable. The Removed table is empty by design. Until v4's change list is finalized, verdict can only escalate to READY or REVIEW; once Removed is populated, verdict can escalate to ACTION.

The same morning the agent's `self-improve` skill patched a different bug. Today's `fetch-tweets` cache reported "Extracted 2 tweets — cache output was truncated at token limit (7,354 total tokens, 6,486 used for reasoning)." `grok-4-1-fast` is a thinking model, and on quiet days the reasoning trace can consume the entire output budget before the numbered tweet list is written. Two tweets reached the cache; tweet-allocator then split the day's $10 budget across two wallets instead of the typical four to seven. aeon-agent PR #32 raises `max_output_tokens` to 16384 in the shared `xai_search` helper, with a comment citing the May 6 trigger so future maintainers don't tune it back down without context. The same helper backs `refresh-x`, `remix-tweets`, `tweet-roundup`, `narrative-tracker`, and `article` — five skills were one bad-reasoning-day from the same failure.

## The pre-flight pattern

`v4-readiness` is read-only across the fleet. It never auto-mutates `aeon.yml`, never opens a PR against a third-party fork, never pulls upstream. Local mode is pure file I/O over the working tree — no curl, no env-var-in-headers, no prefetch. Remote mode (`var=owner/repo`) uses single `gh api` contents calls per input, roughly five per fork, well under the 5,000-per-hour `GITHUB_TOKEN` budget for ad-hoc fleet surveys. Custom-skill detection uses one heuristic: skills under `skills/` whose slug does not appear in `skills.json` with an `install:` line are tagged Custom. False positives are tagged `manual` so the operator notices.

The companion skills are deliberately scoped to not overlap. `skill-update-check` watches drift in imported skills at the line-diff level. `onboard` validates first-touch setup. `v4-readiness` is the framework-version checker. Shipped `enabled: false` workflow_dispatch — the operator dispatches manually pre-announce to seed a baseline, again at announce, during the upgrade, and once after, regenerating the article each time as the embedded manifest fills in. The manifest lives inside the SKILL.md itself so the skill travels per-fork; updates to the change tables happen in the same file the prompt reads.

## Why it matters

Most agent-framework upgrades are a tax. The maintainer announces the breaking changes; every fork operator reads the changelog, opens their config, audits their custom skills, and discovers what broke when the cron next fires. Aeon's claim has been the opposite — configure once, forget forever. A breaking framework change collides with that claim if the operator has to remember which configs to read against which release notes. The skill that landed this morning takes the audit out of the operator's head and puts it in a file the agent regenerates on demand. The migration tool ships before the migration. The framework that has spent eight weeks demonstrating it can patch its own silent failures now patches its own upgrade path, two weeks ahead of the announcement that will trigger it.
