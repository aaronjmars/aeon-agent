# Week in Review: Three Hardening Layers Ship; Phylax Moves From Opt-In to Always-On

*2026-06-29 — Weekly shipping update*

> Aeon's most substantive runtime hardening sprint to date landed this week — capability tiers, issues-as-state, and votable health all reached production in four days — while an external contributor's security scanner moved from a standalone skill into the mandatory skill-review pipeline.

## What Shipped

### Capability tiers, issues-as-state, and votable health all ship in one sprint

Five PRs over four days (Jun 22–25) ported the hardening roadmap from `aeon-dev` into production, all authored by aaronjmars with two same-day bug fixes.

**Easy wins first (#547, 1c04e30):** `notify` now validates message format before sending, `verify_output` checks that a skill actually produced output before auto-committing, `compact_logs` trims verbose cron logs, `schedule_clusters` prevents concurrent runs of the same skill, and `prune_skills` removes stale disabled-skill artifacts. Each is independently revertable; none changes the run path for healthy skills.

**§6 capability tiers (#548, 81cc340):** Skills now declare a tier (`write` / `read` / `network` / `none`), and `skill_mode.sh` enforces the corresponding tool allowlist before the skill runs. The change touches 38 files across `.github/`, `scripts/`, and `skills/` — a 785-line addition that makes it impossible for a skill to call tools outside its declared surface. The `write` tier is the prior default and is a verified superset, so existing skills are unchanged.

**§3 issues-as-state and §7 votable health (#548, #550, b7573fb):** Cron state now dual-writes — every run still commits `cron-state.json`, but also appends to a pinned `aeon:cron-state` GitHub Issue. The Issue becomes a tamper-evident audit trail without a separate logging layer. Votable health wires 👍/👎 reactions on `skill:health` issues into the repair queue: a skill with a thumbs-up bubble up to the top of the repair priority list without the operator touching a config file.

Both §3 and §7 shipped off by default in #548, then the next PR (#550) flipped them to on-by-default after aaronjmars validated the paths. Two bugs surfaced and were fixed same-day: #552 (db4600b) caught that GitHub Actions coerces an unset `HEALTH_ISSUES` var to numeric `0`, silently disabling votable health — the fix changes the gate from a `!=` comparison to an explicit string match. #553 (ec6a98a) caught a missing `issues: write` permission in `chain-runner.yml` and a path that failed to discover skills with no `var:` field.

### Phylax's ALLOW/WARN/DENY scanner becomes mandatory in skill review

Three weeks ago, Phylax (usephylax) shipped `phylax-audit` as a standalone opt-in skill: paste a remote SKILL.md URL, get back a deterministic verdict before you `./add-skill` it. This week, that scanner moved inside the wall.

`feat(skill): add phylax-audit` (#537, 764cd11) was the original merge — a 124-line skill that runs three independent scans: static (prompt-injection markers, exfil patterns), onchain (Base contract reputation via `mainnet.base.org`), and endpoint (x402 payment rails, API surface). A single composite score returns ALLOW, WARN, or DENY.

`feat(skill-triage): add Phylax onchain + endpoint security pre-screen` (#544, 0346752) wired it into the review pipeline. `skills/skill-triage/SKILL.md` now inline-executes `phylax-audit` on every inbound skill PR that references a Base contract address or payment endpoint — the results fold into the triage report before a human reviewer sees the PR. The reviewer gets an ALLOW/WARN/DENY verdict alongside the existing static scan, not instead of it.

Phylax closed the loop the same week: #545 (18792de) wrapped the example threat strings in inline-code so the skill's own documentation doesn't trip the scanner it describes.

### vuln-scanner's Private Vulnerability Report endpoint actually works now

`vuln-scanner` had a silent 403 on every `POST /security-advisories` call against a repo you don't own — wrong endpoint. The GitHub API has two paths: the bare endpoint creates a public advisory and requires admin or security-manager rights; the reports endpoint (`/security-advisories/reports`) is the actual Private Vulnerability Report flow. #557 (4962c31) swaps the endpoint, pins API version `2022-11-28`, and ports the corrected disclosure flow from aaeron. The diff is 17 lines in `skills/vuln-scanner/SKILL.md`, but it's the difference between a skill that silently fails and one that can actually file a PVR.
