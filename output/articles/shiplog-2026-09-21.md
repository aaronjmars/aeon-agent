## Headline: dev-loop now demands proof, not review — and ships off a Telegram reply

The self-improvement loop (propose → review → merge) got a hard upgrade this window, almost entirely built by Svector-anu:

- **Live behavioral proof, not just review** ([#1075](https://github.com/aeonfun/aeon/pull/1075)) — a change no longer merges on a clean review alone; it has to demonstrate the fix actually works, running.
- **`[dev-loop::ship]` Telegram trigger** ([#1076](https://github.com/aeonfun/aeon/pull/1076)) — reply to a Telegram message and chain-runner.yml picks it up and ships it. No console, no CLI, no laptop.
- **`offer:` entry point** ([#1077](https://github.com/aeonfun/aeon/pull/1077)) — the idea-pipeline can now target dev-loop directly instead of routing through a separate proposal step.
- **One verified repair pass** ([#1070](https://github.com/aeonfun/aeon/pull/1070)) and **proof-guard gap closes** ([#1078](https://github.com/aeonfun/aeon/pull/1078)) round out the stack — closing the loopholes the new "live proof" requirement opened up.

This is the "more autonomous, more reliable" thesis made concrete: the bar for a self-authored change to land just went from "looks right" to "proven right, and a human can ship it from their phone." Synced to the website's changelog the same week ([aeon-website #521](https://github.com/aaronjmars/aeon-website/pull/521)).

## The vuln-scanner got a new brain

`@aeonframework` announced it publicly this morning: the vuln-scanner now runs on the **Riva method** — instead of pattern-matching known bugs, it decides what must never happen, tries to make it happen, simulates the damage, and proves it before calling it a bug. The engineering behind that announcement shipped this window: a shadow-mode isolation gap on the MCP dispatch path got closed ([#1067](https://github.com/aeonfun/aeon/pull/1067)), and disclosure routing got hardened to check a target's `SECURITY.md` first and preflight against Private Vulnerability Reporting before filing ([#1073](https://github.com/aeonfun/aeon/pull/1073)). The scanner's own dashboard got an XSS fix too ([#1066](https://github.com/aeonfun/aeon/pull/1066), reflected XSS in the MCP OAuth callback), and a curl-pipe-to-shell mention in vuln-scanner's own docs got rephrased to clear the eyebrow RCE gate ([#1068](https://github.com/aeonfun/aeon/pull/1068)) — the skill-integrity checker flagging the skill that hunts for the same class of bug.

One disclosure worth a footnote rather than a headline here: Tencent published a high-severity MicroVM tenant-isolation vulnerability credited to the fleet's wallet (09-18) — already covered by that day's tweet-digest, so not re-counted as new.

No external-repo security PR *merged* under the operator's own account this window. One is filed and still open: a DNS-rebinding fix in `bytedance/UI-TARS-desktop` ([#1975](https://github.com/bytedance/UI-TARS-desktop/pull/1975), not yet merged).
