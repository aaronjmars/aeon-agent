## Aeon Connect: the onboarding flow finally ships

The headline ship of the window, and the biggest single chunk of PR volume (39 PRs in a new `aeon-connect` repo, plus supporting work in `aeonfun/aeon`): **a hosted, one-shot onboarding flow at `aeon.fun/connect`.** Sign in with GitHub, pick a model, and your instance spins up as a fork of `aeonfun/aeon` with repo-scoped tokens — no local clone, no hand-editing `aeon.yml` to get a first run. Supporting pieces landed across the window: `aeonfun/aeon` #1158 (`aeon init` + a credential manifest with a drift test), #1157 (one-shot model connect, live connect-check, setup checklist), #1163 (docs now lead onboarding with Aeon Connect instead of the clone instructions), plus a mobile-friendly dashboard pass (works on phones, Pull/Push in a drawer) and security hardening on the connect flow itself (OAuth callback escaping, same-origin gate, CSRF closed via the install-redirect callback, API rate limiting). Both the `aeon-agent` and `miroshark-aeon` live-instance forks got a docs PR this window pointing new visitors at Connect instead of the old fork-and-configure path — this is the priority-zero "lower the barrier to fork" work landing as a real, shipped surface rather than docs promises.

## OpenAI renamed their own agent off our name

Continuing narrative rather than a new story: OpenAI renamed their internal agent product from "Aeon" to "Dots." The team treated it as validation rather than a threat — "they renamed their agent from Aeon to Dots 🤷‍♂️ great validation," "we made @sama an offer he couldn't refuse," "is #openai copying us? we are the real Aeon" — and shipped a comparison blog post (`aeonframework` tweet, Oct 1) walking through what's actually different (mostly auditability). Thin on new code, thick on distribution: the original "is OpenAI copying us" post hit 4,125 views, "we made @sama an offer" hit 5,437.

## New skill: feedback-builder

Shipped this window and already getting cited: **feedback-builder** turns user `/feedback` reports into PRs automatically — your agent-users file bugs, Aeon clusters the pile and ships the best request as a real pull request. Framed as a direct response to a request from `@brian_armstrong` on X. Spotlighted via `aeonframework` #1096 on `aeonfun/aeon` (merged), with the companion tweet picking up 28 likes / 3,077 views.

## Security batch: a sandbox escape closed, a critical Next.js bump

A heavier-than-usual security window on `aeonfun/aeon`:
- #1132 — **closed a sandbox escape**: the read-only `bwrap` root wasn't actually read-only by default, allowing a parent-rename escape
- #1114 — a full audit batch: dashboard bind, workflow injection, sandbox, `secretcurl`, webhook, installers
- #1122 — pinned third-party harness installers and locked later-step paths
- #1107 (dashboard) — bumped Next.js to 16.3.8 for a critical RCE advisory
- aeon-connect's own OAuth/CSRF/rate-limit hardening (above)

On the product side, `aeon.fun/security` picked up sort-by-latest and filter-by-severity on the leaderboard, with two new wins logged (microsoft/mxc RUSTSEC-2026-0190, Graphify GHSA-pcc4). The operator also posted two reminders this window that aeon agents audit hook contracts and general smart contracts, not just their own code (75 likes / 4,547 views), alongside a "Securing Crypto like an agentic boss" video recap (43 likes / 4,483 views).
