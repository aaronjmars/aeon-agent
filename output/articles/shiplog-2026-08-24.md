## The headline: an external contributor fixed a secret-leak vuln in our own security wrapper

`Svector-anu` — a blockchain engineer with no prior tie to this repo — opened and got **8 PRs merged into `aeonfun/aeon`** this window. Not driveby typo fixes: real bugs, found by reading the codebase closely enough to catch things we missed.

The standout is **#935**: `secretcurl.sh` substitutes `{ENV_NAME}` placeholders so a skill's command line never shows a literal `$SECRET` to the Bash permission analyzer — but the substituted value was then handed to curl as plain **argv**, which means the real secret sat in curl's own process command line, readable by any other process on the box via `ps` or `/proc/<pid>/cmdline`. Every write-tier skill already has `Bash(ls:*)`/`Bash(cat:*)` on its allowlist, so a malicious or injected skill could have scanned `/proc` for a live `secretcurl` subprocess with tools already granted — no privilege escalation required. The substitution mechanism did half its job: kept the secret out of the command *the script* evaluates, not out of the command *curl* evaluates. Fix routes args through curl's `-K`/`--config` on stdin, the one invocation form where values never touch argv.

The rest of the batch, all merged:
- **#874** — `aeon-update` was silently deleting a currently-enabled skill if it got retired upstream, instead of leaving it alone.
- **#932** — dispatch failures were truncating their own diagnostic output, hiding the reason a skill failed right when you need it most.
- **#933** — `skills/feature` and `skills/changelog` both instruct agents to run `cd <dir>` as a standalone Bash call (the documented workaround for the sandbox blocking `&&`/`;`/`|` chaining) — except `cd` was never actually granted, so the officially-recommended pattern failed every time.
- **#934** — the skill-runner's concurrency group wasn't scoped by target, so unrelated runs could block each other.
- **#936** — `state_store.sh` and `health_issue.sh` both do "search for an issue by title, create if missing" with no atomicity; `gh`'s own search has documented index lag, so two concurrent callers could both see "not found" and both create a duplicate. Converged the ensure paths.
- **#937** — the Telegram webhook wasn't deduping updates by `update_id`, so a retry could dispatch the same command twice.
- **#941** — added `fx`, Vercel's new native (Zig) coding-agent CLI, as a 7th run-harness. Verified against a real locally-built binary, not just the docs — full native MCP support, no npm/pipx install step.

Zero of these were solicited. This is the "self-repair loop" thesis STRATEGY tracks — but from outside the fleet instead of inside it. Ecosystem growth isn't just forks and stars; an unaffiliated engineer auditing your security wrapper closely enough to catch an argv leak is the strongest signal a framework is real enough to be worth reading.

## The launch: aeon runs from inside Claude Code now

**#884 / #885** package the existing `aeon` operator skill as a distributable Claude Code plugin:
```
/plugin marketplace add aeonfun/aeon
/plugin install aeon@aeon
```
Set up an instance from scratch, edit schedule/skills, turn a chat into an automation, edit `STRATEGY.md`/`SOUL.md` — all from inside Claude, no separate clone-and-configure step. This shipped 08-17 (start of this window) and got promoted 08-23 in the window's top-performing post (64 likes, 16 RT) — the ship and the announcement landing in the same window is the loop working as designed: build, then show the work so it spreads (STRATEGY priority 2).
