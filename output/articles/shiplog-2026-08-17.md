## The core: aeonfun/aeon — 7 merged PRs, and one of them was a priority-zero bug

The headline isn't a feature, it's a fix. **`bin/add-skill` could not install a single skill from any repo using the standard `skills/<slug>/SKILL.md` layout** — the layout all 74 skills in this repo actually use (#866). Two separate bugs stacked: skill discovery only searched 2 directories deep (`skills/<slug>/SKILL.md` sits 3 deep, so it never matched — "No skills found in \<repo\>" for every repo), and the install step didn't resolve the `skills/` subdirectory at all. Verified end-to-end against `aeonfun/aeon` main and, notably, against a real community fork — `Autonomy-Labs-Tech/aeon` (one of last week's new forkers) — pulling the in-flight `taskmarket-delegate` branch. That's the fork-onboarding path STRATEGY calls a priority-zero bug, and it was silently dead for anyone trying to add a skill to a fork.

Riding alongside:

- **`taskmarket-delegate`** (#865) — a new skill that lets the agent delegate to [TaskMarket](https://taskmarket.dev), an agent-worker task market, instead of burning inference on unreliable or low-confidence work. Browse (no key) ranks open tasks winnable-first; create/submit sits behind an explicit operator authorization gate and degrades cleanly without `TASKMARKET_API_KEY`.
- **Fleet-wide CVE patch** — `nanoid` (CVE-2026-67213) got bumped to 3.3.17+ same-day across **6 repos**: `aeonfun/aeon` (#871), `aaronjmars/aeon-agent` (#173), `aaronjmars/miroshark-aeon` (#127), `MiroShark/MiroShark` (#286), `aaronjmars/aeon-website` (#248), plus the operator's own side projects (`magi` #31, `blank-page-prototyping` #26). Same disclosure, same day, six independent PRs — the self-repair loop doing what it's supposed to.
- **Heartbeat learned from its own false positive** (`aeon-agent` #174) — the daily heartbeat kept re-flagging minitor's `SECURITY.md` as missing because it only checked the repo-root path; the file lives at `.github/SECURITY.md`, a valid GitHub location. Fix adds a re-verify step across root/`.github/`/`docs/` before reporting a community-health file missing, instead of re-notifying a stale finding every 48h.
- **vuln-scanner picked up cargo-fuzz** (#863, #868) — fuzz targets a repo already ships, staged toolchain + widened sandbox grant.
- **ECOSYSTEM.md** gained Finance District (#869).
- **Docs sync** caught the repo back up to the website (#873, aeon-website #245/#247/#248/#250/#251) — including a new "aeon on the Wire" blog post (#247).

7 of aeonfun/aeon's 7 commits this window were merged PRs — a quiet week by commit count, dense by consequence.

## Ecosystem — a discoverability blitz: ~38 awesome-lists in one day

On 2026-08-16 the bounty-discovery loop fired off "Add Aeon" PRs to roughly **38 awesome-list and directory repos** in a single day — `awesome-claude-skills` variants, `awesome-mcp-clients`/`-servers`, `awesome-ai-agents`, `awesome-telegram`, `coinbase/x402`, `langfuse/langfuse-docs`, and more. Four are **already merged**: `remotion-dev/remotion` (#10485, **56.5k ⭐** — a genuinely high-profile placement in their resources/tooling docs), `abordage/awesome-mcp` (#93), `milisp/awesome-codex-cli` (#99), `Chat2AnyLLM/awesome-repo-configs` (#148). The rest are sitting open for maintainer review; 2 duplicate submissions closed unmerged and were correctly not resubmitted twice. This is the "lower the barrier to fork" thesis pointed outward — get Aeon in front of the people who curate what builders find first.

Also: `xpaysh/awesome-x402#1226` is a **correction**, not a new listing — fixing an existing Aeon link to point at the canonical `aeonfun/aeon` repo post-transfer.

No external (non-operator-owned) **security** PR merged this window — the nanoid fixes above all landed inside the operator's own fleet, not someone else's repo. That's the marquee story to watch for next window.
