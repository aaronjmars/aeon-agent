## What Shipped

### Grok Build: first harness that isn't Claude

The biggest structural change this week: aeon added Grok Build (xAI's CLI agent) as a full peer harness (#585–#590, #622, #624). Not a wrapper. A first-class harness on par with Claude Code, with its own AGENTS.md, MCP wiring, and run-shaping flags.

The key unlock is the Claude→grok compatibility layer (#590) — skills are written for Claude's tool interface, and the compat layer translates them so every existing skill runs unchanged on grok. Connect with your @X account or @grok subscription and the framework routes correctly. The dashboard auto-detects when you switch harnesses and pushes the config (#624).

This is the "harness is the model" thesis made concrete. aeon now supports the two most capable agent CLIs without needing to rewrite a single skill.

### Telegram is now a full control surface

Three PRs (#591, #593, #594) turned Telegram from a notification sink into a bidirectional control surface:

- Force-reply and inline buttons wired across 16 skills
- "Run again / Schedule weekly" button on every skill notification
- Auto-register slash commands when you save a Telegram token (via the dashboard)
- Re-register button in dashboard for manual refresh

Every skill you run now generates a mobile control interface. You can re-trigger or schedule anything from your phone without touching GitHub Actions.

### Skill library pruned: 102 → 69

- **#603**: retired 25 skills (94 → 69), including 3 from core

Plus **#604** cleaned dangling references and **#601** dropped a stale SHOWCASE fork row. The curation decision is deliberate: the library was sprawling, and "69 well-maintained skills" is a cleaner fork target than "102 skills of variable quality." Moving from skill marketplace to skill generator (TBD) as Aaron put it on X.
