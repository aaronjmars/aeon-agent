DeFiLlama TVL Column (47th column type)
Minitor now has a column that watches every DeFi protocol's total value locked in real time. Three modes ship with it: a top-protocols leaderboard sorted by current TVL, a 24h-gainers view that surfaces which protocols are pulling in capital fastest right now, and a chains view that aggregates TVL by network (Ethereum, Base, Arbitrum, Solana, BSC, etc.). An optional category filter narrows the leaderboards to Dexs, Lending, Liquid Staking, Restaking, CDP, Yield Aggregator, or any other DeFiLlama category by substring match.

Why this matters:
The May-18 article proposed an IndieHackers RSS column to fill the bootstrapper/indie gap between Product Hunt and HN. Problem: indiehackers.com no longer publishes RSS — /feed, /feed.xml, /posts.rss, /podcast.rss all return the SPA shell. The idea was based on an outdated assumption from when IH did expose RSS years ago. Rather than ship dead URLs, this PR pivots to a column that's a much stronger fit for minitor's actual audience: roughly a third of the active fork cohort runs crypto-focused decks (wallet-tx, polymarket, coingecko already live), and yesterday's CoinGecko column merge (PR #44) made the on-chain cluster the natural place for a TVL companion. CoinGecko covers price + market cap; DeFiLlama covers TVL + protocol-level signal — different axis, zero overlap. Both ship keyless.

What was built:
- lib/integrations/defillama.ts (~220 lines): keyless fetcher against api.llama.fi/protocols (~3k entries) and api.llama.fi/v2/chains (~200 entries). Mode-specific sort (TVL desc / 24h-change desc with TVL tiebreaker / chains TVL desc), optional category substring filter, drops protocols with TVL ≤ 0 to suppress dead entries, keeps CEX entries (Binance CEX, Coinbase Custody) because watching custody concentration is part of the use case.
- lib/columns/plugins/defillama/plugin.ts: Zod schema (mode enum + free-text category string), DefillamaConfig + DefillamaMeta types (tvlUsd, tvlChange24h, tvlChange7d, category, chains, marketCapUsd, kind discriminator). #445ed0 DeFiLlama brand blue accent — distinct from wallet-tx #627eea Ethereum blue, polymarket #2D9CDB electric blue, coingecko #8DC647 green. Layers lucide icon, evokes the L1/L2/app stack and is visually distinct from the other on-chain icons.
- lib/columns/plugins/defillama/server.ts + client.tsx: server fetcher uses PAGE_SIZE-based cursor pagination; client renders brand chip + category pill + relative time on the meta row, lazy-loaded protocol logo + canonical defillama.com/protocol/{slug} link in the body, TVL + green/red 24h delta arrow + optional 7d delta + protocol token mcap + chain list in the stats row.
- 3 registry edits (manifest.ts, registry.ts, server-registry.ts) — 1-line import + 1-line registration each, matches the existing pattern. The server-registry parity check at module init throws loudly if any of the three drift.
- README.md: intro paragraph picks up DeFiLlama, Apps & on-chain cluster row 5 → 6, total column count 46 → 47, keyless list updated.

How it works:
The /protocols endpoint returns the full DeFiLlama scrape in one call (~2-3 MB raw JSON, edge-cached at the CDN so the per-request cost is negligible). The integration normalises each protocol's TVL, % change, category, chain list, and logo URL into a FeedItem<DefillamaMeta>, sorts according to mode, applies the optional category substring filter, and slices into PAGE_SIZE pages. Gainers mode breaks ties on absolute TVL so a $50M protocol moving 20% ranks above a $50k protocol moving 20% — without that tiebreaker the leaderboard would be drowned in noise every time a new token launches. The /v2/chains endpoint is the only chain-list URL stable across DeFiLlama API rewrites; v1 was deprecated 18 months ago. Protocol logos load via <img loading="lazy"> against icons.llamao.fi — same approach as the CoinGecko column, so a deck full of DeFi rows doesn't waterfall.

What's next:
DeFiLlama exposes ~30 more endpoints (per-protocol historical TVL, yield pools, stablecoin supply, fees + revenue, bridge volumes, NFT marketplaces). The most natural follow-on for the AEON operator audience would probably be a Yields column — top APY across the same protocols — or a Stablecoins column tracking which chains stablecoin supply is migrating to. Both reuse the same integration shape.
