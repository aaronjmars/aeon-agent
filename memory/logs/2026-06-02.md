- **Pick rationale**: May-30 idea #5 (column data export) already shipped as PR #56 on May-31. No ai-build issues. No memory/MEMORY.md priorities tied to minitor. Picked the next natural UX-density feature in the per-column UX axis (tab groups May-29 → column collapse May-30 → JSON export May-31 → quick-search Jun-02). Operators run 47+ column types and frequently need to find one item in a deep-scrolling column without reconfiguring persistent include/exclude rules. Quick-search is the missing ephemeral-narrowing view.
- **What**: 3 files, +228/-7. New `searchByColumn: Record<columnId, string>` view-state map in use-deck-store (NOT persisted — same lifetime as autoFetchingIds / selectedTabByDeck / collapsedColumnIds). New `itemMatchesSearchQuery(item, query)` helper in keyword-match.ts (single literal substring, case-insensitive, scans same content + author + url haystack as itemMatchesAlertKeywords). Search button in column-card.tsx header between alert/filter badges and Refresh; toggles a thin input row below the header. Esc clears + closes; `×` button clears in place. Search badge in header shows X/N count when active.
- **Key design decisions**:
  1. **View-state only, never persisted** — searches don't survive a reload, don't export with the deck, don't fire webhooks. The line that separates this from include/exclude.
  2. **Search narrows; never widens** — runs on top of include/exclude. Operator who set `exclude: spam` and searches `discount` still won't see spam-with-discount; persistent filter wins.
  3. **Single literal substring, not a parsed keyword list** — typing `rust foo` means the phrase, not `"rust" OR "foo"`. Reusing parseAlertKeywords would have OR-split.
  4. **Auto-open on render when query exists** — cross-tab/cross-collapse case: search persists in-session and the bar reappears when operator comes back.
  5. **Collapsed strip search indicator** — small emerald Search icon when search is active on a collapsed column. Prevents the silent-undercount surprise where matchCount badge would shrink under a hidden filter.
  6. **256-char query cap** — defensive against runaway paste; no operator types a 200-char query.
- **NO DB schema, NO migration, NO server round-trip, NO plugin contract touched** — pure view-state work. Same shape as PR #55 (collapse) and PR #53 (tab groups, in-session selectedTabByDeck).
