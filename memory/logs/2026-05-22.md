## Self-Improve — notify substring matcher → word boundary
- **PR**: https://github.com/aaronjmars/aeon-agent/pull/57
- **Branch**: improve/notify-word-boundary
- **What**: `.github/workflows/aeon.yml` defines `./notify` via heredoc; the diagnostic-probe suppression block used glob substring matching (`*test*|*trace*|*ping*|*debug*`) to silently drop Claude's verification probes. Substring matching also dropped any real notification under 120 chars containing `test`/`trace`/`ping`/`debug` inside another word — "Latest token-report", "Shipping 3 PRs", "Tracer code", "Pinging operator" all silently swallowed. Same broken pattern existed in the post-run pending-notify replay block. Replaced both with a bash regex word-boundary matcher (`^[^a-z]*(test|trace|ping|debug)([^a-z]|$)`), kept `hello`/`hi` as exact-trim matches, and lowered the length threshold from 120 → 60 chars (real diagnostic probes are very short).
- **Why**: No specific log entry — the failure mode is silent (skill logs "notification: sent" but notify exited 0 having sent nothing). Risk is general: every skill calls `./notify`, several skills (star-milestone, star-momentum, repo-pulse one-liners, heartbeat short verdicts) produce notifications under 120 chars. With "Latest" / "Shipping" / "Tracer" as plausible first words in real notifications, the substring matcher was a silent-suppression hazard.
- **Files**: `.github/workflows/aeon.yml` (two blocks: ./notify heredoc + pending-notify replay)
- **Status**: PR opened
